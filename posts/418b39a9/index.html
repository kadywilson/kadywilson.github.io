本地智能桌宠

发表于 2026-05-23 分类于 捣鼓日记 阅读次数：

Introduction

契机

  • 写 oc 写上头，让 gemini 给我画了 oc 的 q 版小人，之后突发奇想觉得可以做一个 Windows 本地智能桌宠，遂开工。
  • 其实也是想尝试一下不同 effort level、haiku/sonnet 的性能差异。

现在他能做什么

  • 目前这个桌宠已经可以正常作为日常小工具使用。核心功能大概可以分成几块。

1. 桌宠本体

  • 桌宠是一个透明背景、无边框、始终置顶的小窗口。它不会自己乱跑，只能用鼠标拖拽移动，这样不会打扰正常使用电脑。

  • 现在的交互是：

    • 按住桌宠拖动：移动位置
    • 双击桌宠：触发 AI 回复
    • 气泡出现后：点击气泡关闭
    • 托盘菜单：显示、隐藏、打开待办、打开日志、退出

  • 隐藏桌宠之后，程序不会退出，只是桌宠和气泡不显示。需要的时候可以从系统托盘重新显示；真正退出则通过托盘菜单里的 Quit 。

2. AI 对话气泡

  • 双击桌宠后，它会先显示“我想想……”之类的等待气泡，然后调用 SiliconFlow API 生成回复。回复以气泡形式显示在桌宠上方。

  • AI 回复会受到人设配置影响，比如名字、性格、语气、时间段规则、禁词等。这样它不是每次机械地说一句“你好”，而是会比较像一个固定性格的角色。人设配置文件可以自由修改。

  • 我还给它设置了情绪表情。AI 返回的结果里包含：

  • 程序会根据 emotion 切换对应的表情图。目前支持：

    • default
    • happy
    • annoyed
    • upset

3. 自定义人设

  • 人设写在 config/persona.yaml 里，可以自己改。

  • 比如可以改：

    • 桌宠名字
    • 年龄
    • 性格
    • 说话风格
    • 不同时间段的语气
    • 情绪规则
    • 禁词
    • 硬性规则

  • 笨蛋 AI 一到了晚上就觉得桌宠会 annoyed，因此后来专门加了规则：深夜可以关心我休息，但不要每次都生气。这样回复就自然很多。

  • 角色资源放在：

  • 另外建议表情图使用透明背景 PNG，不然桌宠会有奇怪白底。

5. 待办事项窗口

  • 桌宠带了一个本地待办事项窗口，可以从托盘打开（点击Open Todo）。

  • 现在支持：

    • 新增待办
    • 编辑待办
    • 删除待办
    • 标记完成 / 取消完成
    • 设置截止时间
    • SQLite 本地保存
    • 重启后待办仍然存在

  • 数据保存在：

  • 界面最开始非常原始，像默认 Qt 表格。后来又单独做了几轮 UI 优化，包括按钮样式、日期选择、表格列宽、输入框对齐、避免 QSS 样式污染等。

6. DDL 智能提醒

  • 不会主动说话的oc不是好oc（）

  • 程序会每 60 秒扫描一次未完成的待办。如果待办没有过期，就会在两个时间点提醒：

    • 截止前一天
    • 截止前半小时

  • 已经完成的待办不提醒，已经过期的待办也不会再提醒。

  • 提醒内容不是死板模板，而是会根据待办内容调用 AI 生成个性化提醒。例如：

    • 如果是考试：提醒复习，祝考试顺利
    • 如果是作业：提醒早点开工、记得提交
    • 如果是组会 / meeting：提醒准备材料、别迟到
    • 如果是出去玩：提醒带东西、看天气、玩得开心
    • 如果是论文：提醒保存文档、检查格式

  • 我后面还修过一次提醒 AI 的问题。一开始 reminder 逻辑疑似调用了不存在的方法，导致它可能一直走 fallback。本来以为已经接入了 AI，后来通过日志检查才发现要确认真实调用路径。修复后，DDL 提醒有了专门的 generate_reminder_reply()，还加了日志标记，能判断到底是走 AI 还是 fallback。

  • 日志里可以搜索：

  • 如果看到类似：

  • 就说明真的走了 AI。

  • 如果 API 失败、网络失败、返回格式不对、或者包含禁词，就会自动 fallback 到本地模板，不会让程序崩掉。

GPT

  • GPT 在这个项目里更像“项目经理 + 咨询顾问 + 流程监控”。

  • 我主要用它做这些事：

    • 把需求拆成阶段

    • 写给 Claude Code 的 prompt
    • 遇到 bug 时判断是哪里的问题

  • 实际体验是：GPT 不直接改我的代码，但非常适合帮我想清楚“该让 Claude Code 做什么”。

Claude Code

  • Claude Code 是主要的编程工具。

  • 咨询了GPT之后，交替使用 Haiku 和 Sonnet：

    • Haiku：进行小修小补、文档增量更新、明确的小 bug。这次编程主力是Haiku。
    • Sonnet：进行读项目结构、总结状态、复杂一点的修复。笨蛋Haiku的bug就让Sonnet来修，同时形成总结文档方便我开启新对话减少token消耗。
    • Medium effort：开发目前功能的话完全够用。
    • High effort：已老实，感觉Medium够用了。

Procedure

  • 整个项目大概是这样迭代出来的。

Stage 1：桌宠窗口 MVP

  • 先做最小可运行版本：

    • 显示桌宠图片
    • 透明背景
    • 无边框
    • 置顶
    • 鼠标拖拽
    • 双击显示气泡
    • 托盘显示 / 隐藏 / 退出

  • 这一步完全不接 AI。先让桌宠本体稳定。

Stage 2：表情差分系统

  • 让桌宠表情丰富起来，通过 manifest.json 读取：

    • default
    • happy
    • annoyed
    • upset

  • 并支持调整尺寸。这样后续换皮肤、换表情不会碰核心代码。

Stage 3：接入 AI 回复

  • 双击桌宠后调用 SiliconFlow API，生成短回复和 emotion。

  • 重点是：

    • API 失败不能崩
    • JSON 格式错误要 fallback
    • 不能在 UI 线程里阻塞
    • 不能打印 API key

Stage 4：人设配置和气泡体验

  • 加入 persona.yaml，把性格、姓名、时段规则、禁词等从代码里拿出来。

  • 同时优化气泡：不要 2 秒自动消失，而是停留到用户点击关闭（都是气泡了，戳一下消失，很合理）。

Stage 5：待办窗口和 SQLite

  • 做 TodoWindow，支持新增、编辑、删除、完成，保存到 SQLite。

  • 这一阶段只做管理界面，不做提醒。

Stage 5.5 / 5.6 / 5.7：美化和修 UI

  • 这一步花的时间比想象中多。默认 Qt 控件实在是丑陋，而且样式很容易互相污染。

  • 修过的问题包括：

    • 按钮没颜色
    • 日期选择按钮不可见
    • 标签文字模糊
    • 表格列宽不对
    • 日历弹窗被染色
    • 列表行背景太突兀

  • 由于没有什么平面设计审美和经验，最后的版本貌似也不是很好看，但是够用。后续应该会进行优化。

  • 经验是：QSS 一定要控制作用域，不要乱写全局 QWidget 样式。

Stage 6：DDL 智能提醒

  • 加入定时扫描：

    • 前一天提醒
    • 前半小时提醒
    • 未完成才提醒
    • 过期不提醒
    • 桌宠隐藏时不弹气泡

  • 提醒内容接入 AI，根据待办内容个性化生成。

Stage 6.5：静默启动和日志

  • 把日常启动改成不显示黑色控制台窗口。日志写入文件，调试时再用 bat 查看控制台。

文档整理：README 和 PROJECT_STATE

  • 最后补文档：

    • README.md：给人看的使用说明
    • PROJECT_STATE.md：给未来 Claude Code 看的项目交接文档

  • 这样以后开新会话不用 /resume，直接让 AI 读 CLAUDE.md 和 PROJECT_STATE.md 就能继续开发。

Discussion

不要一口气让 AI 写完整项目

  • 如果一开始就说“帮我写一个智能桌宠，带 AI、todo、提醒、托盘、配置、自定义皮肤”，AI 很容易生成一堆互相耦合、难以调试的代码。

  • GPT告诉我的方式是：

GPT 帮我润色的 prompt

  • 我后来给 Claude Code 的 prompt 基本都有这些结构：

    • 当前已经完成什么
    • 本次只做什么
    • 明确不要做什么
    • 允许修改哪些文件
    • 不允许碰哪些文件
    • 运行方式是什么
    • 完成后要汇报什么
    • 如何测试

  • 这会极大减少它“自作主张”。

UI 样式的作用域

  • PySide6 的 QSS 很容易影响不该影响的控件。

  • 我遇到过：

    • 待办窗口样式影响日历弹窗
    • 按钮被设置成透明
    • 标签文字变模糊
    • 表格行背景不合理

  • 后面才开始给窗口和控件设置 objectName，用更精确的选择器，例如只作用于 TodoWindow，避免污染 PetWindow 的透明背景。

单击拖拽和双击

  • 桌宠是靠鼠标拖拽移动的。如果把单击也设成 AI 触发，很容易影响拖拽体验。

  • 最后我保留了：

    • 单击 / 拖拽：移动
    • 双击：触发 AI

  • 这个交互比较稳定。

AI 结果 fallback

  • 不要相信模型永远返回正确 JSON。它可能返回正常 JSON，也可能返回带 markdown 代码块的 JSON，甚至可能输出一段解释。

  • 所以必须做：

    • JSON 解析失败 fallback
    • emotion 不存在 fallback
    • API key 缺失 fallback
    • 网络失败 fallback
    • 禁词命中 fallback

  • 这样桌宠才不会因为一次 API 异常就崩掉。

日志失格

  • 我一开始以为 DDL 提醒已经接入了 AI，后来看到待确认项才意识到应该验证。

  • 后来通过日志标记：

  • 来确认提醒到底是：

    • 成功调用 AI
    • API 失败
    • JSON 解析失败
    • 命中禁词
    • 走 fallback

  • 没有日志的话，很难判断“看起来智能”到底是真 AI 还是模板（主要是模板也不是我自己写的，啊哈哈）
